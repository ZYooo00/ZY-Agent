# SOP：新增培養液品項（以 GIVF → GX-IVF 為範例）

> 適用情境：廠商停產舊品、引進新品牌／新型號培養液，需要在系統上線一個「全新品項」時使用。
> 目前先針對 GIVF → GX-IVF 這一款寫，日後卵子培養液（或其他類別）比照本流程調整即可。

---

## 什麼時候該走這份 SOP

- 廠商通知舊品項全面停產／停止供貨，改由新品項取代
- 引進一款全新的培養液/試劑，過去系統裡完全沒有這個品項
- **不適用**：只是換批號、換包裝規格，但本質上還是同一個品項 → 直接在既有品項底下新增進貨紀錄即可，不需要這份 SOP

---

## 銜接原則：舊品項不刪除，新品項並行上線

1. 舊品項（例如 GIVF）**保留在 `products_config`，不刪除歷史文件**。等現有批號全部用罄、確認不會再進貨後，才把它設定為 `hidden: true`（在後台品項維護畫面切換「停用」）。
   - 不要提前刪除或隱藏，否則正在使用中的批號會從盤點/庫存頁面消失，扣庫存與報廢計算也會跟著失效。
   - 過渡期間讓新舊兩個品項同時存在、同時可被選用，操作端不會被迫在某一天「切換」，可以自然地把舊批號用完。
2. 新品項（例如 GX-IVF）透過 `admin.html` 後台「新增品項」建立一筆新文件，欄位參考下方「新增品項欄位檢查表」。

---

## ⚠️ 關鍵限制：備盤頁（beipan.html）不會自動長出新卡片

`beipan.html` 顯示哪些培養液/試劑可以備盤，是由寫死在前端程式碼裡的 `reagentConfig` 陣列決定（`beipan.html` 約第 1155 行起），**不是**單純讀 `products_config` 動態產生。

**這代表：單靠後台新增一筆 GX-IVF 品項資料，備盤頁不會自動出現對應的備盤卡片。**

必須額外請工程師（或 Claude）在 `reagentConfig` 陣列裡手動新增一個物件，比照現有 `givf` 物件的欄位（`id`、`name`、`label`、`bottleVol`、`batches` 等），這一步驟**不能省略**，也是目前系統唯一「新增品項需要動到程式碼」的地方。

（`admin.html` 品項維護畫面本身也有這行提示：「若新增的是全新的培養液/試劑類別，備盤頁不會自動出現對應卡片，需要工程師協助開發。」）

## 新增品項欄位檢查表（Admin 後台品項維護）

| 欄位 | 說明 | 範例（GX-IVF） |
|---|---|---|
| `id` | 系統內部代號，全小寫、不重複 | `gx-ivf` |
| `name` | 顯示名稱 | GX-IVF |
| `vendor` | 廠商，需對應 `order.html` 裡的 `VENDOR_META` 廠商清單 | 亞樸 |
| `brand` | 品牌，**沒有品牌一定要留空白讓它存成 `null`，不要打任何字**（詳見下方「已知資料陷阱」） | Vitrolife（若共用同品牌）|
| `unit` | 計量單位 | 瓶 |
| `bottleVol` | 單瓶容量（mL），影響開封後用量計算 | 60 |
| `expiry` | 開封後效期（天） | 7 |
| `pandianGroup` | 盤點分組，**務必選一個既有分組**，沒選的話這品項不會出現在盤點頁 | VitroLife |
| `gupanId` | 估盤頁對應 ID，格式通常是 `m-` 或 `f-` 開頭 | `m-gxivf` |
| `target` | 安全庫存量 | 依實際狀況 |
| `reorderQty` | 建議訂購量 | 依實際狀況 |

## 上線後檢查清單（依序走過 7 個系統）

| 系統 | 檔案 | 檢查項目 |
|---|---|---|
| 後台設定 Admin | `admin.html` | 新品項欄位是否都正確填寫、有跳出「盤點群組」與「備盤頁需工程協助」的提醒 |
| 估盤（手機） | `gupan.html` | 新品項是否出現在估盤清單 |
| 庫存盤點（手機） | `pandian.html` | 新品項是否出現在對應盤點分組 |
| 今日備盤 | `beipan.html` | **前面已改 `reagentConfig` 後**，確認新品項卡片正常出現、可選批號、開封效期規則正確套用 |
| 進貨記錄 | `jinhuo.html` | 可以選到新品項作為入庫對象，入庫後庫存數字正確累加 |
| 庫存總覽 | `kucun.html` | 新品項庫存數字正常顯示，手動登記使用功能正常 |
| 訂貨管理 | `order.html` | 依 `brand`/`vendor` 正確分組顯示（`brand` 若誤存成空字串 `""` 而非 `null`，會同時被兩個分類函式濾掉、整個消失——這是已修正過的已知資料陷阱，見下方說明） |

## 已知資料陷阱：`brand` 欄位空字串 vs `null`

`order.html` 判斷一個品項要分到「有品牌」（MEDIUM_CONFIG）還是「無品牌、依廠商分組」（ORDER_CONFIG），依據是 `brand` 欄位**必須明確是 `null`**：

```js
// 有品牌
if (!p.gupanId || !p.brand || p.hidden || p.paused) return;
// 無品牌，走廠商分組
if (!p.gupanId || p.brand !== null || p.hidden || p.paused) return;
```

如果 `brand` 存成空字串 `""`（而不是 `null`），兩個條件都會判定要跳過，品項就會從訂貨管理頁面**整個消失**，且不會有任何錯誤訊息。

`admin.html` 已修正：品項詳細資料的品牌欄位若清空存檔，現在會正確寫回 `null`，不會再存成 `""`。新增品項時若沒有品牌，一樣讓輸入框保持空白即可，不用擔心。

---

## 舊品項下線時機

- 舊品項（GIVF）所有批號**確認用罄、且不會再進貨**後，才在 Admin 後台把它設為「停用」（`hidden: true`）
- 下線後歷史批號的入庫/扣庫存/報廢紀錄仍保留在 Firestore，不會被刪除，之後查歷史用量報表時還找得到
- `beipan.html` 的 `reagentConfig` 陣列裡舊品項的物件建議保留（不要刪除），避免過去備盤紀錄在讀取時找不到對應設定而出錯

---

## 之後套用到卵子培養液時的調整重點

- 卵子培養液若有多款需要同時上線，逐款走一次本 SOP，不要一次改多個 `reagentConfig` 物件再一次測試（風險較高，出錯不好排查）
- 若卵子培養液的計量單位或開封規則跟 GX-IVF 不同（例如不是以瓶計、沒有開封效期限制），欄位檢查表要對應調整，`beipan.html` 新增的 `reagentConfig` 物件結構也要照實際規則寫
